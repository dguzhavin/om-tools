# py-sdk-probe — стенд проверки Python SDK Optimacros

Стенд вызывает все публичные методы `os_ws_sdk` 1.0 (Workspace 9.200) на тестовой модели и
записывает факт: что вернул метод, в каком формате, какие файлы создал, сколько занял и какую
ошибку выбросил. По результатам четырёх прогонов написан справочник
[os_ws_sdk_reference.md](os_ws_sdk_reference.md): как SDK работает на самом деле, его баги и обходы.

## Состав

| Файл / папка | Что это |
|---|---|
| `sdk_probe.py` | Стенд. Один файл, настройки из `.env` |
| `requirements.txt` | Зависимости. Wheel `os_ws_sdk-1.0-py3-none-any.whl` положить рядом (в PyPI его нет) |
| `.env.example` | Все переменные стенда с комментариями |
| `env_examples/` | Готовые `.env` для тестовой модели `PY_SDK ##1.0`: прогон 2 (чтение), 3 (запись), 4 (админка) |
| `reports/` | `report.json` всех четырёх прогонов от 12.10.2026. E-mail пользователей и чужие модели замаскированы |
| `model/` | Бэкап тестовой модели и описание её объектов |
| `os_ws_sdk_reference.md` | Справочник для команды |

## Запуск

```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env                                  # или env_examples/run2_read.env.example
# вписать OM_TOKEN и объекты своей тестовой модели
python sdk_probe.py
```

Результат появится в `OM_WORK_DIR`: `report.md`, `report.json`, `results/*.csv` (полученные
DataFrame), `export/<группа>/<вызов>/` (файлы каждого экспорта).

## Порядок прогонов

1. **Чтение:** `OM_SKIP_WRITE=1`, `OM_TEST_ADMIN=0`. Ничего не меняет в модели. Из `results/*.csv`
   берутся id объектов для следующих прогонов.
2. **Запись:** `OM_SKIP_WRITE=0`. Создаёт и удаляет временные справочники `SDK_PROBE_<время>_*`,
   очищает и восстанавливает мультикуб-приёмник, меняет и откатывает формулу, права и UAM,
   запускает скрипт.
3. **Админка:** `OM_TEST_ADMIN=1`, `OM_GROUPS=admin`. `recalculate`, `backup`, `stop`/`start`.
4. **`restore()`** — отдельно, с `OM_TEST_RESTORE=1`. Откатывает модель к бэкапу.

Запускать только на тестовой модели. После прогона с записью проверить глазами, что приёмник и
формула вернулись в исходное состояние.

## Тестовая модель

Стенд рассчитан на модель с такими объектами (их создают вручную в интерфейсе):

| Объект | Что нужно |
|---|---|
| `SRC_MC` | Мультикуб: время (месяцы), версии Actual/Forecast, кубы `куб_1`=1, `куб_2`=2, `куб_3`=3, `bool_cube` (TRUE только в Jan–Feb 21), одно сохранённое вью |
| `DEST_MC` | Мультикуб той же структуры, что `SRC_MC`, с другими значениями — приёмник для записи |
| `SDK_PROBE_LIST` | Справочник на 5 элементов с одним вью |
| `UAM TEST` | Справочник с включённым UAM |
| `SDK_PROBE_ROLE` | Роль в справочнике Roles |
| `scr1` | Скрипт `console.log("hi!");` |
| Дашборд | С гридом `SRC_MC` на нём |
| Оптимизационный запрос | Пустой (для заполненного стенд выгрузит LP) |

Бэкап такой модели — в папке `model/`.
